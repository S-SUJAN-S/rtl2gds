# WSL Environment & Project Progress Documentation

## Overview
This document serves as a record of the environment setup and progress made towards building the autonomous LLM-driven RTL-to-GDSII flow.

## 1. Project Migration to WSL
To ensure maximum compatibility with open-source Electronic Design Automation (EDA) tools, the entire project workspace was migrated from Windows to the Windows Subsystem for Linux (WSL).
* **WSL Distribution**: Ubuntu
* **Project Directory**: `~/rtl2gds`

All flow configuration JSONs, Python Agent orchestration scripts, and diagram assets were successfully mirrored into this native Linux directory.

## 2. Automated Setup Script (`setup_wsl.sh`)
An automated bash script was developed to instantiate the complete foundational environment inside WSL. The script handles:
1. **System Packages**: Updating `apt` repositories.
2. **EDA Toolchain**: Downloading and installing native binaries for:
   * `yosys` (Logic Synthesis)
   * `verilator` (Linting and fast simulation)
   * `iverilog` (Functional simulation)
   * `klayout` & `magic` (Physical design verification & GDSII viewer)
3. **Python Environment**: Instantiating a virtual environment (`venv`) to isolate the LLM automation stack.
4. **Python Dependencies**: Installing `google-generativeai`, `pydantic`, `networkx`, `matplotlib`.
5. **Cocotb & Pyverilog**: Specifically patched the installation to support Python 3.14 via the `COCOTB_IGNORE_PYTHON_REQUIRES=1` flag to prevent wheel build failures during setup.

## 3. Physical Design Flow & PDK Setup
To support the backend physical design process (Place and Route, DRC, LVS), the following components were fully installed and configured:
1. **Docker Engine**: Installed natively in WSL to run the pre-compiled EDA containers, avoiding complex localized C++ source builds.
2. **OpenLane Ecosystem**: Cloned the official OpenROAD/OpenLane repository and pulled the required Docker images containing `OpenROAD`, `TritonRoute`, and `OpenSTA`.
3. **Volare & SkyWater 130nm PDK**: Used OpenLane's `volare` (via `make pdk`) to automatically download, decompress, and index the entire open-source Sky130 PDK (including standard cells, tech LEFs, and SRAM macros).

## 4. Current System State
The environment is now **100% complete and fully initialized**:
* **Root Execution**: Initial `apt-get` system installations were run autonomously via WSL root access, bypassing the need for manual `sudo` password entry.
* **Virtual Environment**: Python dependencies and the LLM execution stack are safely isolated at `~/rtl2gds/venv`.
* **Flow Readiness**: Every single EDA engine, Python framework, and technology node configuration (Sky130) is fully instantiated and ready for synthesis and physical routing.

## 5. Next Steps in the Development Pipeline
With the complete infrastructure built, the next phases will involve:
1. Drafting the Python LLM Agent (`rtl_to_gds_llm_agent.py`) to parse Verilog ASTs and hook into OpenLane's Python APIs.
2. Pushing a functional HDL module (like the `test_counter.v` or `full_adder.v` we verified) through the automated Place and Route loop.
3. Implementing the LLM-driven feedback mechanism to automatically debug synthesis or timing violations generated by OpenSTA.
